# NiceTool 页面场景

仅在新增或重构页面时，按任务选择章节。视觉基线见 `design.md`。

## 目录

- 查询与列表
- 表单与录入
- 详情与审阅
- 操作型工具
- 统计与分析
- 双栏工作区

## 页面叙事与构图

页面通常由四个角色组成，按需组合，不必全部出现：

```text
Context  当前对象、范围或结果摘要
Control  输入、筛选、动作
Focus    主数据、主表单或主结论
Support  说明、关联、历史、口径
```

### 1. 查询与列表：结果优先

```text
上下文行：结果数 / 当前范围                         新增或刷新
筛选表面：2–3 个高频条件                  重置  查询
主数据表：工具栏 / 表格 / 分页
```

规则：

- 数据表是焦点，筛选区不应比结果区更抢眼。
- 首次进入可直接加载时，不显示空洞的“请查询”占位。
- 复杂筛选默认只展示高频项，其余放入“更多筛选”。
- 结果摘要写“128 条 · 3 个条件 · 更新于 10:32”，不要再加一排统计卡。

### 2. 表单与录入：分段完成

```text
上下文行：当前对象 / 一句话说明 / 状态
主表单：基础信息 ─ 业务配置 ─ 影响范围
辅助区：预览、风险或提交影响
动作栏：取消 / 保存草稿                         提交
```

规则：

- 按用户决策顺序分组，不照搬数据库字段顺序。
- 8 个以上字段分为 2–4 个语义区；短字段使用响应式两列。
- 长表单使用页底动作栏；关键提交按钮在滚动后仍容易找到。
- 危险或不可逆影响在提交前展示，不藏在成功通知里。

### 3. 详情与审阅：结论先于字段

```text
身份摘要：名称 / 编号 / 状态                         主操作
关键信息带：3–5 个最重要字段或判断
主体：分组详情 / 明细 / 时间线
辅助：关联对象、来源、备注
```

规则：

- 先回答“这是什么、现在怎样、需要我做什么”。
- 不把详情做成一列几十行键值对。
- 审批、核对、差异场景优先展示差异和风险，再展示完整原始数据。

### 4. 操作型工具：状态接力

```text
输入表面：文件 / 参数 / 范围                         运行
状态带：校验结果 / 进度 / 当前步骤
结果区：摘要 + 异常 + 下载或后续动作
```

规则：

- 初始状态突出输入；完成后降低输入权重并突出结果。
- 长任务显示当前步骤，禁用重复运行。
- 完成后保留可查看的业务结果，不要只弹 toast。批量任务显示处理数量、异常数和
  适用的下一步；单对象检查显示状态、耗时等与任务相关的信息。
- 结果下载与重新运行分主次，不能出现两个同权实心按钮。

### 5. 统计与分析：问题驱动

```text
范围与口径
核心结论 / 2–4 个指标
主图表或对比表
明细与口径说明
```

规则：

- 先定义分析问题，再选择图表。
- 单页通常 1 个主图和最多 2 个辅助图；没有趋势或比较问题时用表格。
- 指标卡只展示能改变判断的指标，不展示容易从表格数出的数字。

### 6. 双栏工作区：选择影响预览

当左侧选择会持续改变右侧内容时，使用双栏：

```python
with ui.grid().classes(
    "w-full grid-cols-1 lg:grid-cols-[minmax(18rem,0.8fr)_minmax(0,2fr)] gap-4"
):
    with ui.card().classes("w-full").props("flat"):
        ...  # 选择、配置、目录
    with ui.card().classes("w-full min-w-0").props("flat"):
        ...  # 预览、详情、结果
```

不要用双栏展示两个互不相关的任务。移动端必须自然回落为单列。
