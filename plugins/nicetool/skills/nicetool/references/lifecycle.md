# NiceTool 生命周期与调试闭环

由当前 Agent 推进循环，不启动额外模型执行器。沿用 `SKILL.md` 中的目标、文件、环境和授权。
下列命令省略 `python3 "$NICETOOL_SKILL_ROOT/scripts/tool-cli.py"`；全局参数放在子命令之前。
已知环境时每次远程命令使用相同 `--env <env>`，不因错误切换环境。

## 选择起点

| 当前任务 | 第一个动作 |
|---|---|
| 本地生成或修改 | 编辑 → 静态校验；无需读取本文件其余流程 |
| 已有预览报错 | `--json prelog <project> <name> --lines 60`，已有 token 则 `prelog <token>` |
| 本地工具运行报错或要求验证 | 校验 → `--json preview <project> <name> --file <file>` |
| 正式工具报错 | `toollog <project> <name> --lines 60`；它只读本机 `logs/tools`，远端日志不可用时获取用户提供的错误证据，不拿预览日志冒充正式日志 |
| 授权发布 | 校验待发布文件 → `--json publish <project> <name> --file <file>` |
| 授权删除 | 明确环境和目标 → `--json delete <project> <name> --yes` |

`create` 仅写本地文件；不调用服务端、不创建版本。已有修改可直接编辑文件，无需再执行 create。
本地缺失的正式工具用 `get ... --output <file>` 获取，避免完整源码进入 CLI 输出。
发布缺少待发布内容时定位已确认文件或澄清，不自动下载旧版本后重新发布。

## Preview → observe → repair

1. 静态校验通过后上传固定预览，保存返回的 `preview_url` 和日志目标。
   同一环境、同一 `project/name` 复用预览；仅一次性实验使用 `preview --file <file>`。
2. 仅要求生成预览链接时交付链接。要求验证或修复时，有浏览器能力就打开/刷新该链接，
   检查页面及与请求相关的交互；没有浏览器则报告未验证，不把上传成功当成验证完成。
   页面未打开可能还未执行工具，空日志不代表成功。业务写入需有相应授权。
3. 命令失败先读取返回的 `code/message/next_action`；页面失败读一次 `prelog --lines 60`。
   JSON 日志默认保留末尾最多 8000 字符并标记 `truncated`；堆栈不全才增大
   `--lines` / `--max-chars`。不要以 `--grep` 截断首次堆栈，不用 `--follow` 阻塞循环。
4. 按当前错误定位最小修改 → 静态校验 → 更新同一预览 → 刷新并重现原失败步骤。
   只依据本轮时间和操作对应的错误；日志可能残留旧异常，不因旧文本重复修改。
5. 请求的页面/交互验证通过即结束。有具体新证据则继续修复；同一错误在修复后仍出现时
   先更换诊断方法。如果已经没有新证据或可执行的修复，停止相关循环并报告阻塞点和所需输入。

配置缺失、401/403、服务不可达或依赖不可用不属于可盲改代码解决的失败。
保留已完成工作，只在外部条件改变后重试；不清空日志、不重建工具或重复发布来碰运气。
不重复读取未变源码/参考、不重复获取已知资源清单，不为成功的操作追加无目的查询。

## 正式写入与结果不明

- 发布/部署/上线是同一 `publish` 动作，上传本地内容；首次发布由服务端创建索引和 v1，
  不先调用 create。默认文件按 CLI 项目根解析，显式 `--file` 可避免目录歧义。
- 发布、删除需要目标与环境明确的授权；复用已有授权。生产操作先读
  [environments.md](environments.md)，有授权后使用 `--yes`，不让交互确认卡住 Agent。
- 超时或断连不证明写入失败。发布先 `status`，必要时 `get --output <临时文件>` 比较远端
  内容与待发布文件；已达成则结束。删除只读核实目标是否仍存在，鉴权失败不等于不存在。
  若仍不能确定结果，报告不确定状态，不能再次写入；确认未生效后才在原授权内重试。
- 发布成功只需给出正式访问 URL；无核实需要时不再查 status、hash 或版本。

## 结束证据

交付文件/链接及已完成的检查；区分“静态通过”“预览已创建”“页面/交互已验证”“已发布”。
未验证阶段和实际阻塞点明确说明。仅发布工具不代表授权执行工具中的业务写入。

## 工具标识与发布输入

正式工具 project/name 仅接受小写字母、数字、下划线和连字符，长度分别不超过 100/197，name 不带 `.py`。非法名称直接报错，不替换或规范化。发布必须上传源码；缺少输入时定位本地文件或询问用户，不调用空请求重发服务端当前版本。`get --output` 只保存源码，不生成额外状态文件；API 不提供乐观锁冲突保护。
