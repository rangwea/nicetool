# 升级与恢复

[返回文档索引](README.md)

## 演示环境

更新代码后重新执行 `sh scripts/demo.sh`。数据库卷保留，但演示初始化会将内容不同的预置工具写为新版本，可能覆盖你对这三个工具的修改。请将自定义改动保存为其他工具名。重置会删除演示环境中的全部修改，命令见[演示指南](demo.md)。

## 当前开发契约

项目尚未上线，接口调整直接同步服务端、CLI、Skill 和文档，不保留旧行为兼容入口。发布必须上传源码，工具名称严格校验；详见 [API 导航](api.md)。

## 正式部署

1. 记录当前代码提交与镜像版本，备份 MySQL 和运行配置。
2. 对比新旧 `models/` 与 `scripts/init.sql`。建表脚本不是增量迁移工具；启动的 `create_tables()` 不会为已有表自动修改列和索引。
3. 在隔离数据库上验证所需的结构迁移和数据恢复。
4. 使用新的 `uv.lock` 重建镜像，明确注入正式配置。
5. 停止旧实例，执行已经验证的迁移，启动新实例。
6. 验证登录、项目权限、工具预览、发布、运行及日志。

HTTP `/health` 返回 `OK` 只是存活检查。还应实际运行一个使用数据源的工具。

## 回滚

如果仅更换了应用代码，可切回记录的镜像。涉及不兼容数据库变更时，需恢复配套数据库备份，不能只回滚代码。工具版本回滚只恢复工具源码，不撤销工具已经产生的业务数据写入。

## 诊断与反馈

可先运行 `python3 scripts/doctor.py --server <实例地址>`。提交问题时附上提交版本、部署方式、诊断输出、复现步骤和脱敏日志，不要附上真实 `.env`、Token 或数据库备份。
